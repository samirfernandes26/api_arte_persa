# Armazenamento no S3

## Visao geral

O projeto usa `AWS SDK v3` com `@aws-sdk/client-s3` e `@aws-sdk/s3-request-presigner`.

Objetivo:

- armazenar imagens e arquivos grandes fora do banco
- expor upload direto via URL pre-assinada
- persistir apenas metadados no MySQL
- aplicar criptografia server-side com `SSE-KMS` por padrao

### Politica de criptografia no bucket

Todos os uploads gerados por `ServicoS3` aplicam criptografia server-side:

- modo padrao: `aws:kms`
- fallback configuravel: `AES256`

Quando o modo `aws:kms` esta ativo, o backend envia:

- `ServerSideEncryption: 'aws:kms'`
- `SSEKMSKeyId: <AWS_KMS_KEY_ID>`

Quando a URL pre-assinada de upload e gerada, a API tambem devolve os cabecalhos obrigatorios:

- `x-amz-server-side-encryption`
- `x-amz-server-side-encryption-aws-kms-key-id` quando KMS estiver ativo

## Fluxo recomendado de upload

1. Frontend pede URL pre-assinada em `POST /api/uploads/url-pre-assinada`
2. API devolve `url`, `metodo`, `chave`, `cabecalhos`, `url_publica` e metadados de criptografia
3. Frontend faz `PUT` direto para o S3
4. Frontend chama a rota de confirmacao correspondente
5. API grava apenas `chave_s3`, `url_arquivo` e metadados

## Pastas e convencoes de chave

As chaves sao geradas em [src/uploads/uploads.service.ts](../src/uploads/uploads.service.ts).

| Tipo de destino | Pasta gerada |
| --- | --- |
| `foto_inicial_item` | `ordens/{ordemId}/itens/{itemId}` |
| `imagem_observacao` | `ordens/{ordemId}/observacoes` |
| `imagem_adicional_ordem` | `ordens/{ordemId}/imagens-adicionais` |
| `assinatura_cliente` | `ordens/{ordemId}/assinaturas` |
| `arquivo_cliente` | `clientes/{clienteId}/arquivos` |
| `pdf_ordem_servico` | `ordens/{ordemId}/documentos` |
| `pdf_fatura` | `faturas/{faturaId}/pdf` |

Formato da chave:

```text
{prefixo}/{timestamp}-{uuid}-{nome-normalizado}
```

## O que vai para o banco

O banco nao armazena binario. Apenas:

- `chave_s3`
- `url_arquivo`
- `nome_arquivo`
- `tipo_mime`
- `tamanho_bytes`
- metadados de dominio, como `rotulo` ou `ordem_exibicao`

## Envelope encryption para metadados sensiveis

O bucket usa `SSE-KMS` para o objeto em repouso no S3, mas isso nao substitui a criptografia de campos sensiveis no banco.

Por isso o projeto tambem usa `KmsService` para:

- criptografar dados sigilosos em nivel de aplicacao
- encapsular uma data key por registro
- suportar rotacao de CMK sem reescrever o schema

## Tratamento de erro e logging

O `S3Service`:

- registra logs de upload, exclusao e geracao de URL
- encapsula falhas em `InternalServerErrorException`
- valida expiracao positiva para URLs pre-assinadas
